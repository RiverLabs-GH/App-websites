# mark-o

The marketing website for **mark.O**, a private, offline Markdown workspace for macOS. *Read. Write. Organise.*

The app lives in its own repository: [RiverLabs-GH/mark.O](https://github.com/RiverLabs-GH/mark.O) (private).

A static single-page site built with Vue 3, TypeScript and Vite. The build prerenders the page to plain HTML, so it has real content before any JavaScript runs, and hydrates afterwards.

## Run locally

Requires Node.js 22.

```sh
cd mark-o
npm install
npm run dev        # http://localhost:5173
```

| Command | What it does |
|---|---|
| `npm run dev` | Dev server with hot reload |
| `npm run build` | Type-check, build, prerender, write `sitemap.xml` and `robots.txt` into `dist/` |
| `npm run preview` | Serve `dist/` locally |
| `npm run check` | Check `dist/` after a build: links, assets, SEO tags, no third-party requests (the same check CI runs) |
| `npm run smoke -- <url>` | Fetch a served copy of the site and check it resolves where it says it lives (run by the deploy workflow after publishing) |
| `npm run assets` | Rebuild optimised images, favicon and wordmark from the mark.O repo (see below) |

To check the subpath behaviour exactly as GitHub Pages serves it, put `dist/` at `/App-websites/mark-o/` under any static server and open that URL. All asset URLs are relative, so it also works from any other path.

## Structure

```
mark-o/
├── index.html              SEO, Open Graph, JSON-LD
├── src/
│   ├── components/         Navbar, HeroSection, ProblemSection, ExperienceSection (x2: Markdown Reader, OKF Reader),
│   │                       ProductShowcase, FeatureSection, DifferentiationSection, PrivacySection, FinalCTA, Footer,
│   │                       plus AppWindow (screenshot in a window frame) and DownloadButton
│   ├── data/content.ts     All copy, image references and the download switch
│   ├── data/images.json    Image dimensions (generated by `npm run assets`)
│   ├── styles/             tokens.css (design tokens), global.css, animations.css
│   ├── directives/reveal.ts  Scroll reveal
│   ├── main.ts             Client entry (hydrates the prerendered page)
│   └── entry-server.ts     Server entry used by the prerender step
├── public/                 images/, videos/, favicon/
├── tools/
│   ├── prepare-assets.mjs  Source assets -> web assets
│   └── prerender.mjs       Writes the rendered HTML into dist/index.html
└── .env.production         VITE_SITE_URL (canonical, Open Graph, sitemap)
```

Copy lives in `src/data/content.ts`, not in the components. Every claim there comes from the mark.O repo; do not add one that is not in its docs.

The parent company (RiverLabs.io: name, link, contact email and logo mark) is one `company` entry in `src/data/content.ts`. The footer, the structured data's publisher, the `author` meta tag and the 404 page all read it, and `npm run check` fails if they disagree. The logo mark in `public/images/riverlabs-logo.svg` is a copy of the company site's own favicon (https://river-labs.io/favicon.svg).

## The download button

The site shows **Coming soon for Mac** until the release can be reached by the public. The v0.1.0 release URL is already in `src/data/content.ts`.

When the release is public, set `enabled: true` in the `download` object in `src/data/content.ts`, then rebuild. Nothing else changes.

## Assets

Source assets are read from the mark.O repo, which this module never modifies. `npm run assets` expects it at `/Users/vipinkp/PycharmProjects/mark.O` (override with `MARKO_REPO=/path/to/mark.O`) and produces:

- WebP copies of the raw app screenshots (2000 px wide) and the step-by-step captures (1600 px wide). The finished promo slides in `docs/store-images/` are not used.
- The favicon set and a transparent wordmark, both cropped from the official `icon.png`.
- The bundled Inter and JetBrains Mono fonts, copied into `src/assets/fonts/`.

Two files are made by hand with the ffmpeg that ships with the mark.O repo's Remotion install (`product-video/node_modules/@remotion/compositor-darwin-arm64/ffmpeg`; set `DYLD_LIBRARY_PATH` to its folder):

```sh
# 1080p film -> 1280x720 H.264, about 8 MB
ffmpeg -i mark-o-preview.mp4 -vf scale=1280:720 -c:v libx264 -preset slow -b:v 900k -maxrate 1400k -bufsize 2800k \
  -pix_fmt yuv420p -movflags +faststart -c:a aac -b:a 64k public/videos/mark-o-launch-web.mp4
# poster frame at 8 s (also used for the Open Graph card)
ffmpeg -ss 8 -i public/videos/mark-o-launch-web.mp4 -frames:v 1 -q:v 4 public/videos/poster.jpg
```

The film contains Pexels stock footage of a laptop (licence note: `product-video/public/footage/SOURCES.md` in the mark.O repo). The page says the laptop is stock and that mark.O is not endorsed by Apple. The film has no caption track yet.

## CI and deploy

Two workflows live at the repository root in `.github/workflows/`, both scoped to `mark-o/**`:

| Workflow | Runs on | What it does |
|---|---|---|
| `mark-o-ci.yml` | every pull request that touches `mark-o/` | `npm ci`, `npm run build` (type-check, bundle, prerender), `npm run check`. Publishes nothing. |
| `deploy-mark-o.yml` | push to `main` that touches `mark-o/`, or run by hand | The same build and check, then replaces the `mark-o/` folder on the `gh-pages` branch, then runs `npm run smoke` against the live site. A failed check stops the deploy; a failed smoke test fails the run. |

`npm run check` (`tools/check-dist.mjs`) fails the build if the output has: an empty or missing prerender, a root-absolute URL (it would break under the subpath), a missing file or broken `#anchor`, a dangling `aria-controls` or `aria-labelledby`, an image without alt text, a missing title, description, canonical, Open Graph tag, sitemap or robots file, a third-party URL, a network API in the bundle, or a file over 50 MB.

A repository has one Pages site. Each module has its own deploy file and publishes only its own folder on the `gh-pages` branch (`mark-o/` here, `everon/` for the other module), so neither deploy can remove the other's site. The site is served at `https://riverlabs-gh.github.io/App-websites/mark-o/`. The bare `https://riverlabs-gh.github.io/App-websites/` has no page of its own. Setup: Settings > Pages > Source: Deploy from a branch > `gh-pages` (root); the first deploy run creates the branch.

The build also writes a branded `404.html` (self-contained, `noindex`, absolute URLs only, because it is served at any depth). The deploy copies it to the root of the published site, which is the one place GitHub Pages looks for it, and it then answers every unknown address under the site.

The deploy derives the site's address from the repository (`https://<owner>.github.io/<repo>`, or the repository variable `SITE_BASE_URL` for a custom domain) and passes it to the build as `VITE_SITE_URL`. Local builds use `.env.production`.

`npm run smoke` (`tools/smoke-live.mjs`) fetches the live page and checks that its canonical link matches the address it is served at, that the Open Graph image, sitemap, `robots.txt` and every asset the page references resolve, that the video answers range requests, and that an unknown address returns the branded 404 page with a 404 status. It retries a 404 for about a minute, because Pages can take a moment to serve a fresh deploy. The build-folder check cannot see any of this, which is how a deploy once published the site at the wrong address.

### One-time setup

1. Make the repository public. GitHub Pages on a private repository needs a paid plan.
2. In **Settings > Pages**, set **Source** to **GitHub Actions**.
3. Merge to `main`. The site goes live at `https://riverlabs-gh.github.io/App-websites/mark-o/`, and the run's summary shows the URL.

To publish without a code change (for example after flipping `download.enabled`), use **Actions > Deploy mark-o site > Run workflow**.

## Facts the site keeps true

- Fully offline, no account, no analytics, no telemetry.
- macOS builds are ad-hoc signed and not notarized, so first launch needs right-click, then Open (shown in the final section).
- No Windows build is published, so the site does not mention Windows. This is why the handoff's "Is it on Windows?" FAQ answer is not used.
- The AI assistant is Mac-only, runs on Apple's on-device model (mark.O does not supply one), and is never called accurate or always right. It says "a recent macOS" until the assistant is tried on macOS 26 (ticket EP4-011 in the mark.O repo).
- OKF trust labels are advisory, not security. mark.O is not affiliated with Google or Apple.
- No price or privacy-policy page exists, so none is shown. The only contact is the RiverLabs.io email in the footer.
